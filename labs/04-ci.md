# Lab 04 - Connect to CI (15 min)

## Idea
The tests ran on your machine against Docker. CI makes it repeatable for a team:
push, and your AI-edited tests run on a containerized emulator in the pipeline.

## Steps (everyone)
1. Look at `.gitlab-ci.yml`:
   - `validate` runs the device-free checks on every push/MR (fast, runs anywhere).
   - `android-e2e` boots the emulator (docker-android service) and runs `npm run
     android`, saving screenshots as artifacts. It needs a **KVM-enabled runner**
     tagged `kvm` (see FACILITATOR.md; a cloud-device-farm fallback exists too).
2. Push a branch and open a merge request:
   ```bash
   git checkout -b my-mobile-lab
   git push -u origin my-mobile-lab
   ```
   Watch the pipeline in GitLab -> CI/CD -> Pipelines. `validate` goes green for
   everyone; `android-e2e` runs where a KVM runner exists.
3. Review your own MR: do the new tests assert real behavior? Would you approve it?

## Closing discussion
- Where did the AI-CLI speed you up, and where did it need a human gate?
- What rule would you add to CONVENTIONS.md for your real mobile suites?
- How easy was "edit in English -> run on a real device in CI" versus your
  current setup?

## Done when
Your `validate` job is green and you've reviewed your MR.
